# 评分报班比例与 Bob 固定晚班 V1

用户确认的计算口径：按报班可用总小时计算，最高评分目标 80%，其余评分档位先拟定。保留此前关闭“平均工时公平分配”的设置；本次新增的是按评分区分的个人工时目标。

规则文件：`configs/hurstville-business-v1.json`。这是独立、可版本化的 RuleSet 扩展，绑定 Hurstville 和基准 `hurstville:v20`，不会覆盖原有规则或修改数据库 schema。基准版本、门店或员工 ID 不匹配时明确失败。

## 拟定比例

| 评分 | 本次日期范围内报班可用小时的目标比例 |
|---|---:|
| 最高评分（并列同样适用） | 80% |
| 90–100 | 80% |
| 85–<90 | 75% |
| 80–<85 | 70% |
| 75–<80 | 65% |
| 70–<75 | 60% |
| 65–<70 | 55% |
| 60–<65 | 50% |
| 55–<60 | 45% |
| 50–<55 | 40% |
| <50 | 35% |
| 没有有效正式评分 | 不编造目标比例；资格和 Availability 仍独立判断 |

最高评分特殊规则优先，所以即使某个门店最高评分低于 90，该最高分员工仍以 80% 为目标。没有报班时目标小时为 0，不为了比例创造 Availability。

分母为原 Snapshot 中有效 AVAILABLE 区间在本次门店本地日期范围内的并集，合并重复/重叠区间，排除批准休假。原 UNAVAILABLE 否决仍由唯一权威适配器执行。不会把可用班型数量当成报班小时，也不会重复计算 Full。目标精确到分钟；实际班次仍按原规则的 30 分钟合法时段安排。

目标比例是软分配目标，不是最低保证、硬上限、工资工时或正式发布资格。现有实际报班下全部评分目标合计 401.35 小时，而完整一周精确人数要求 402 名义小时；这些比例不可能同时作为人人不能超过的硬上限。员工资格/班型还可能进一步降低个人可安排容量。

实现不止于 Prompt：程序计算每人的目标分钟、已排目标小时、剩余目标和预计超目标分钟，并据此计算候选的 `target_priority_term` 和 `selection_priority`。同一个员工尚未达目标时，能减少更多目标缺口的合法较长班次获得更高候选分；达到目标后减少优先度并惩罚可避免的超额。LLM 最终选择人员，程序只过滤硬约束违法候选、计数和验证，没有增加求解器。

## Bob 硬条件

本次从实时数据库确认员工为 **HandoverEmployee018**，canonical ID 为 `synthetic-employee-018`。规则按 ID 绑定，不按模糊姓名匹配。

- 每周二、周四必须覆盖 **17:00–22:00**。
- 具备现有岗位资格、Availability 覆盖完整时间的 Full 也可以满足。
- 16:00–22:00 或 17:00–22:00 的合法 Late 都满足。
- 17:00 已结束的 Early 不满足晚班；不靠班型名称假装覆盖。
- 当前 Bob 的真实 Availability 允许两个晚班，但当前岗位映射未生成 Full 候选。没有为了满足用户目标自动授予正式岗位、修改技能或放开资格。

每天先由 Daily Agent 选择满足指定员工条件的合法候选，再继续填其他人数。独立 Validator 在每日提交和全周重放时都检查这一条件。Bob 不可用、缺少资格或与固定班次/上限冲突时返回结构化诊断，不能安排别人替代后仍宣称满足 Bob 条件。
