# 交接安全边界与扫描方法

原项目、原 Git 历史、生产配置和数据库保持只读。只在原目录之外创建副本、安装副本依赖、执行合成测试与新建交接 Git 历史。未导出生产数据库 dump，没有轮换/删除原凭据。

导出从已核实 Sites 提交的 git archive 与两个本地工作树取得。排除真 .env、.local/.data、旧 .git、备份、截图、数据库与数据附件、日志、SSH/私钥、真实导出 fixture、托管写入凭据。保留锁文件与源码；品牌 clover PNG 经构建实际引用，其他二进制附件不交付。

内容处理：在私有审计区读取既有本地导出的姓名/个人字段/账号/会话哈希，仅构建内存匹配字典用于检查，字典和原始导出不随包交付；替换明确身份、密码/secret 字面值、provider token 格式、签名 URL。人员合成标签为 HandoverEmployeeNNN，保留同值及大小写不敏感测试关系；恢复“培训”等普通业务词在 UI 标签中的原语义，不把普通词语当员工资料。没有给缺失代码编造空实现。

额外调整只在副本：禁用 build/prepare 和 evaluate-prepare 从原工作区自动取源；hosting 替换为惰性 DB 示例；docker-compose 的密码改为必填变量；增加合成本地工具、文档、校验脚本。完整 SOURCE_FILES 记录每个原始文件和交接文件哈希/差异。构建生成的 assets/metadata 是可重建产物，按 manifest 规则记录，不声称字节等于原提交。

扫描包括：精确已知 secret/人员值、PAT/API key/private-key/JWT 格式、联系字段、异常二进制/数据库文件；人工检查示例和上下文；拟提交所有 Git blob 逐个扫描，而不是只检查工作树。扫描结果/计数见 FINAL_VALIDATION.json。没有匹配不等于形式化证明所有可能敏感信息不存在；仍不应把未审查原历史或外部数据加入交接仓库。

MANIFEST.json 的 files 排除其自身和 SHA256SUMS.txt（防止自引用）；SHA256SUMS 覆盖其余最终交付文件并包含 MANIFEST，排除自身。ZIP 校验值单独存放在包外，不写进包内制造递归哈希。ZIP 的文件列表、逐项哈希与 CRC 完整性由实际重新打开归档验证。Git bundle 若另行提供，仅包含新建已扫描历史，不能包含原仓库历史。

本次不自动邀请开发者、不扩张 GitHub 或 Sites 权限。私有仓库的外部可访问性必须在上传后核实；若工具权限不足会如实标注未上传，不能把 GitHub connected 等同创建/推送成功。
